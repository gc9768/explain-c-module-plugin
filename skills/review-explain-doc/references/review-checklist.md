# review-explain-doc 审核清单

## 事实与证据

- [ ] 每个关键行为都能追溯到源码、构建脚本、日志或明确的模拟示例。
- [ ] 调用者、被调用者、线程和回调关系没有把推测写成事实。
- [ ] 硬件寄存器、电源域、时钟域、睡眠深度和功耗数据标明证据来源或不确定性。

## 结构与教学性

- [ ] 模块职责、入口、调用链、资源生命周期和错误路径完整。
- [ ] 关键函数有图或表，并解释“为什么这样写”和“不这样会怎样”。
- [ ] 专业术语第一次出现时有白话解释，生僻 C 语法没有被一句话带过。

## 图表与格式

- [ ] Mermaid 图语法结构合理，节点和箭头与正文一致。
- [ ] Markdown 与 HTML 的章节、代码片段、结论和危险提示一致。
- [ ] HTML 的折叠面板、代码高亮和外部资源失败时不影响正文阅读。

## 可维护性与安全边界

- [ ] 文件路径、函数名和行号可在当前工作树中定位。
- [ ] 没有泄露密钥、账号、个人路径或不应公开的调试信息。
- [ ] 文档没有暗示已经完成编译、烧录或硬件验证，除非有实际证据。
