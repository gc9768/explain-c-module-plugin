# /explain-c-module 输出文档模板

生成 `doc/explain/md/<模块名>.md`（源）与 `doc/explain/html/<模块名>.html`（阅读版）时，
**两份共用下面这 8 节结构**（HTML 按 `html-template.md` 渲染同一份内容）。模块名作 `#` 一级标题，
各节用 `##`。没有内容可写的节可省略，但 **1 / 3 / 4 / 6 / 8 通常都要有**。

---

# <模块名> 代码讲解

> **模块路径**：`<相对路径>`
> **生成时间**：<YYYY-MM-DD>　|　**讲解深度**：初级（面向刚入行 / 刚转嵌入式的工程师）
> **一句话**：<这个模块到底干什么，用人话>

## 1. 模块概览

- **它是什么**：一段话，讲清这个模块在系统里扮演什么角色。
- **谁调用它 / 它调用谁**：上下游关系（**能从代码/包含关系确认的才写**，别猜）。
- **在系统中的位置**：必要时画一个 ASCII 框图（数据/调用流向：谁 → 谁 → 谁）。

## 2. 前置知识

读这段代码前你需要的最少背景，**1-3 条**，每条一句话白话 +（可选）类比。
只列"不看这俩概念就听不懂下面讲解"的那种，别堆。

## 3. 涉及的嵌入式知识点（核心）

只写**本模块真实命中**的维度（对照 `knowledge-checklist.md` 扫描结果）。每条用三段式：

### <知识点名，如：`volatile` 与内存映射 I/O>
- **是什么**：一句白话 + 类比。
- **为什么用**：在这个场景里不这么干会怎样（讲动机，不是定义）。
- **这段代码怎么用**：贴具体代码片段（**带行号**）+ 中文讲解。

> 命中的维度多的话可以分组小标题；没有命中的维度**整条不要出现**。
>
> 若有值得初学者记住的生僻 C 语法（函数指针、`__attribute__`、`container_of`、指派初始化等），
> 在本节末尾加一个 `### C 语法聚焦`，挑 2-4 处带代码锚点集中讲。

## 4. 逐段讲解

挑最关键的函数 / 段落。每个函数用这个格式：

#### `<函数签名>`
```c
// 代码片段（可只贴关键部分，用 // ... 标注省略）
```
**为什么这样写**：讲设计意图、踩过的坑、为什么不换个"看起来更简单"的写法。
**不复述代码**（"这行给 x 赋值"——没用）。

> 遇到初级读者会愣住的语法（函数指针、`container_of`、`__attribute__`、`do{}while(0)` 宏、
> 指派初始化等），**顺手给一句白话行内注释**解释那处语法，不用单开节。

> 大模块（>10 文件 / 单文件 >800 行）：讲 **5-8 个核心函数**，其余在末尾列表
> （函数名 + 一句话职责）。文档顶部注明"已精简讲解"。

## 5. 重点与难点总结

**3-6 条** bullet，提炼"最容易卡住初学者"的点。每条一句话点透，让人读完"哦原来如此"。

## 6. 常见坑与注意事项

- ⚠️ `<文件:行号>`：<改这里会发生什么 / 为什么容易错>
- ⚠️ `<文件:行号>`：<...>

至少 **2-3 条**；能从代码定位到行号的就给行号。典型坑：ISR 里阻塞、忘开外设时钟、
DMA buffer 没 cache 同步、`volatile` 漏加、临界区太长、栈溢出、优先级反转……

## 7. 延伸学习

本模块**没展开**、但理解它会长期受益的概念清单（bullet）。例如：优先级反转、DMA cache
一致性、链接脚本 (linker script) / 启动流程、原子操作、内存屏障。给方向即可，不必展开。

## 8. 自测小问题

**3-5 个**问题，帮读者检验是否真懂。例如：
- 这段代码里 `x` 为什么必须加 `volatile`？去掉会发生什么？
- 如果把这个阻塞调用留在 ISR 里，系统会怎样？
- `configMAX_PRIORITIES` 设小了，会有什么后果？

## 写作要求（再次强调）

- 中文；代码、标识符、API、MCU 型号保持原文。
- 每个术语**首次出现**给白话 + 类比。
- 表格、ASCII 图能用就用（初始化顺序、中断流程、数据流向、寄存器位布局）。
- **不臆造**：代码用到的才写；不确定的硬件数值标"请查 `<芯片>` 参考手册 (RM)"。
- 行号要准确——讲解时打开对应源文件，引用真实行号。
