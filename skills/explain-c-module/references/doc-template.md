# /explain-c-module 输出文档模板（v2.0）

生成 `doc/explain/md/<模块名>.md`（源）与 `doc/explain/html/<模块名>.html`（交互阅读版）时，
MD 按 8 节结构；HTML 同 8 节骨架但**允许增强**（Mermaid 图/折叠面板/证据框，见 html-template.md）。
模块名作 `#` 一级标题，各节用 `##`。没有内容可写的节可省略，但 **1 / 3 / 4 / 6 / 8 通常都要有**。

> **v2.0 量化指标（生成结束前自查）**：
> - 全文（MD 口径）**图 ≥3 张 + 表 ≥2 张**（ASCII 承载，HTML 升级为 Mermaid）；
> - 第 4 节核心函数**多数配有真实实例**（工程日志/崩溃栈/配置值，见铁律 1）；
> - 每个关键设计至少一处**反事实**（"不这样写会怎样"）。

## 2. 前置知识

读这段代码前你需要的最少背景，**1-3 条**，每条一句话白话 +（可选）类比。
只列"不看这俩概念就听不懂下面讲解"的那种，别堆。

## 2.5 基础知识小课堂（生僻语法详解，独立可读）

凡第 3/4 节代码里出现"初级读者会愣住的语法"（函数指针、`container_of`、`__attribute__`、
指派初始化、`do{}while(0)` 宏、位域、`##` 拼接等），**每个在此单开一小节详细讲**，
不放第 3/4 节行内一句带过（行内只留"→ 详见 2.5.x"）。每小节四段式：

### 2.5.x `<语法名，如：函数指针>`
1. **语法拆解**：把构造逐部分指认——
   ```c
   int (*fp)(int, char);     // 从中间的 fp 读起:fp 是…
   // ① (*fp)  → fp 是个指针  ② (int,char) → 指向"收 int,char 两个参数"的函数
   // ③ int    → 该函数返回 int  ⇒ fp = "指向 int f(int,char) 型函数的指针"
   ```
2. **为什么发明它**：没有它时的替代写法（如函数指针→ switch-case 分发表，代码长且加函数要改两处），
   有它后是什么形态——讲动机，不是背定义。
3. **本代码里的用法**：贴本模块真实使用处，逐行注释。
4. **常见误用**：一两句最容易写错的点（如忘 `(*fp)` 的括号变成"返回指针的函数声明"）。

> 本节定位：读者可以**只读这一节**就补齐对应语法——它是对外的"知识产品"，
> 不是第 4 节的附注。数量按实际出现的生僻语法定，通常 2-5 小节。

## 3. 涉及的嵌入式知识点（核心）

只写**本模块真实命中**的维度（对照 `knowledge-checklist.md` 扫描结果）。每条用三段式：

### <知识点名，如：`volatile` 与内存映射 I/O>
- **是什么**：一句白话 + 类比。
- **为什么用**：在这个场景里不这么干会怎样（讲动机，不是定义）。
- **这段代码怎么用**：贴具体代码片段（**带行号**）+ 中文讲解。
- **实测证据**（有就必加）：一段工程真实日志/现象佐证，标注来源文件。

> 命中的维度多的话可以分组小标题；没有命中的维度**整条不要出现**。
>
> 生僻 C 语法的完整详解**统一放第 2.5 节"基础知识小课堂"**（本节只贴代码 + "→ 详见 2.5.x"）。

## 5. 重点与难点总结

**3-6 条** bullet，提炼"最容易卡住初学者"的点。每条一句话点透，让人读完"哦原来如此"。

## 6. 常见坑与注意事项

- ⚠️ `<文件:行号>`：<改这里会发生什么 / 为什么容易错>
- ⚠️ `<文件:行号>`：<...>

至少 **2-3 条**；能从代码定位到行号的就给行号。典型坑：ISR 里阻塞、忘开外设时钟、
DMA buffer 没 cache 同步、`volatile` 漏加、临界区太长、栈溢出、优先级反转……
**有历史事故的坑**（本工程真实踩过）用 **事故框**格式：现象日志一行 + 根因 + 修复提交/记忆条目。

## 7. 延伸学习

本模块**没展开**、但理解它会长期受益的概念清单（bullet）。例如：优先级反转、DMA cache
一致性、链接脚本 (linker script) / 启动流程、原子操作、内存屏障。给方向即可，不必展开。

## 8. 自测小问题

**3-5 个**问题，帮读者检验是否真懂。例如：
- 这段代码里 `x` 为什么必须加 `volatile`？去掉会发生什么？
- 如果把这个阻塞调用留在 ISR 里，系统会怎样？
- `configMAX_PRIORITIES` 设小了，会有什么后果？

好的自测题应能从**本文引用的实测证据**里找到答案线索，而不是纯背诵。

## 写作要求（再次强调）

- 中文；代码、标识符、API、MCU 型号保持原文。
- 每个术语**首次出现**给白话 + 类比。
- 表格、ASCII 图**必须有**（≥3 图 2 表，v2.0 指标）；初始化顺序、中断流程、数据流向、
  寄存器位布局都是天然画图点。
- **不臆造**：代码用到的才写；不确定的硬件数值标"请查 `<芯片>` 参考手册 (RM)"。
- **实例不臆造**：引用的日志/栈/配置必须真实存在于工程文件，注明来源；找不到实例的点
  明说"（无实测数据，推理）"。
- 行号要准确——讲解时打开对应源文件，引用真实行号。
